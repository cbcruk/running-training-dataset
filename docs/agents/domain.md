# 도메인 문서

엔지니어링 스킬이 코드베이스를 탐색할 때 이 저장소의 도메인 문서를 어떻게 읽어야 하는지.

이 저장소는 **단일 컨텍스트**다: 루트에 `CONTEXT.md` 하나, 공유되는 `docs/adr/` 하나.

## 탐색 전에 읽을 것

- **`CONTEXT.md`** (저장소 루트) — 용어집과 도메인 개요.
- **`docs/adr/`** — 지금 작업하려는 영역에 닿는 ADR을 읽는다.

이 파일들이 없으면 **조용히 진행한다.** 부재를 지적하지 말고, 먼저 만들자고 제안하지도
말 것. `/domain-modeling` 스킬(`/grill-with-docs`를 통해 도달)이 용어나 결정이 실제로
정리될 때 게으르게 만든다.

## 파일 구조

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-dictionary-shape.md
│   ├── 0002-component-model.md
│   ├── 0003-nub-runtime.md
│   ├── 0004-tanstack-router.md
│   ├── 0005-comments-as-agent-context.md
│   ├── 0006-korean-only-dataset.md
│   └── 0007-korean-repo-prose.md
└── src/
```

새 ADR은 기존 번호를 이어간다 — 다음은 `0008-`.

## 언어

**ADR 0006부터 한국어로 쓴다.** 0001–0005는 날짜가 박힌 기록이라 영어로 동결돼 있고
소급해 다시 쓰지 않는다 — [ADR 0007](../adr/0007-korean-repo-prose.md).

## 용어집의 어휘를 쓸 것

출력이 도메인 개념을 이름 부를 때(이슈 제목, 리팩터 제안, 가설, 테스트 이름) `CONTEXT.md`가
정의한 그 용어를 쓴다. 용어집이 명시적으로 피하는 동의어로 흘러가지 말 것.

필요한 개념이 아직 용어집에 없다면 그건 신호다 — 프로젝트가 쓰지 않는 언어를 지어내고
있거나(다시 생각할 것), 진짜 공백이 있거나(`/domain-modeling`을 위해 기록할 것).

## ADR 충돌은 드러낼 것

출력이 기존 ADR과 모순되면 조용히 덮어쓰지 말고 명시적으로 드러낸다:

> _ADR-0003(nub runtime)과 모순됨 — 그래도 다시 열어볼 값이 있는 이유는…_
