# ADR 0011 — 프리렌더를 포기하고 SPA로 간다

**상태:** accepted · 2026-08-16
**대체하는 것:** [ADR 0010](0010-tanstack-start.md)의 프리렌더 결정, 그리고
[ADR 0001](0001-dictionary-shape.md)의 "발견" 절반

---

## 맥락

**저장소 소유자가 프리렌더를 포기하고 SPA로 가기를 요청했다.** 도구는 그대로다 — TanStack
Start의 `prerender` 블록이 나가고 `spa` 블록만 남는다.

이 문서가 할 일은 하나다. ADR 0001이 이 프로젝트의 첫 결정으로 세운 성질을 지금 버리는
것이므로, **정확히 무엇을 버리는지 재서 적는 것**이다. 물려받은 숫자로는 안 된다. ADR 0004가
Start를 거절하며 인용한 표(SPA 셸에서 첫 엔트리 2,942 ms)는 다른 빌드, 다른 계측에서 나온
것이고, 그 숫자로 지금을 설명하면 틀린다.

그래서 두 상태를 **같은 하니스로 오늘 다시 쟀다.** 프리렌더 빌드는 바로 앞 커밋(719e316)을
worktree에 체크아웃해 그대로 빌드했다.

## 결정

**`prerender`를 끄고 `spa`만 남긴다. 검색 코퍼스는 번들로 되돌린다.**

빌드가 내놓는 문서는 셸 하나이고, `404.html`은 그 복사본이다(`scripts/pages-404.ts`).
GitHub Pages는 파일이 없는 경로에 `404.html`을 주므로, 그 둘이 같은 바이트인 것이 정적
호스트에서 히스토리 API 라우팅을 쓰는 표준 방법이자 서버 재작성 규칙이 필요 없는 유일한
방법이다.

셸에는 라우트 내용이 없다. 문서 하나가 **모든** URL에서 하이드레이트되므로, 어느 한 URL에
치우친 마크업을 담으면 나머지 전부에서 하이드레이션이 깨진다 — ADR 0010이 홈 문서를 404로
복사했다가 정면으로 맞은 실패(React #418)가 그것이다.

### 검색 코퍼스는 번들로 돌아간다

ADR 0009가 코퍼스를 `/search-index.json`으로 뺀 이유는 프리렌더된 문서 47개가 각자 코퍼스를
싣게 되는 것을 막으려던 것이었다. 문서가 하나뿐이면 그 이유가 없다. 그래서 검색은 다시
네트워크를 타지 않고(`app/client/search.tsx`), ADR 0009가 손실로 기록했던 성질이 돌아온다:
**한 번도 열지 않은 엔트리도 오프라인에서 검색된다.**

## 잰 것

배포 base(`/running-training-dataset/`) 아래에 정적 서빙, Chromium, Fast 3G + 4× CPU 스로틀,
캐시 없음, 3회 중앙값. 대상은 `/anchor/rpe_10`.

|                              | 프리렌더 (ADR 0010) | SPA (지금)          |
| ---------------------------- | ------------------- | ------------------- |
| 엔트리가 보이기까지          | **309 ms**          | **317 ms**          |
| 딥링크 문서의 HTTP 상태      | **200**             | **404**             |
| 링크 언퍼러가 보는 `<title>` | `rpe_10 · …`        | 사이트 제목 하나    |
| 링크 언퍼러가 보는 본문      | **2,336자**         | **177자** (셸 뼈대) |
| 클라이언트 JS (gzip)         | 148.9 kB            | 149.1 kB            |
| `dist/client` 전체           | 1,372 kB (문서 49)  | 544 kB (문서 2)     |

**속도는 이 이동의 비용이 아니다.** 309 ms 대 317 ms이고, 이 차이는 측정 노이즈 안에 있다.
ADR 0004가 인용한 2,942 ms는 이 빌드에서 재현되지 않는다 — 그때는 라우트별 코드 분할이 없는
단일 번들이었고, 지금은 셸이 3.5 kB에 엔트리 라우트 청크가 3–8 kB다.

**비용은 두 가지다.** 첫째, 딥링크가 **HTTP 404를 돌려준다.** 파일이 없으니 GitHub Pages가
그렇게 답할 수밖에 없고, 정적 호스트에는 고칠 방법이 없다. 사람에게는 보이지 않지만 크롤러
에게는 "이 페이지는 없다"는 말이다. 둘째, **엔트리별 메타데이터가 디스크에서 사라졌다.**
`<title>`·description·canonical·OG는 이제 하이드레이션 뒤에야 붙고, 링크 프리뷰는 그때까지
기다려주지 않는다. 어떤 URL을 공유해도 사이트 제목 하나와 177자의 셸 뼈대가 보인다.

그 둘을 합치면 ADR 0001이 "발견"이라고 부른 절반이다. 이 이동이 실제로 포기하는 것이 그것
이고, 속도가 아니다.

## 결과

**얻은 것**

- **오프라인 검색이 완전해졌다.** 코퍼스가 번들에 있으므로 한 번도 열지 않은 엔트리도
  검색된다. ADR 0009가 "실제 손실"이라고 적었던 것이 되돌아왔다.
- **검색이 네트워크를 타지 않는다.** 첫 질의에서 fetch가 한 번 나가던 왕복이 없어졌다.
- **배포 산출물이 1,372 kB에서 544 kB로 줄었다.** 문서 49개가 2개가 됐다.
- **빌드가 짧아졌다.** 프리렌더가 라우트마다 렌더하던 48회가 1회가 됐다.

**치른 것, 그리고 남은 함정**

- **위의 표 전부.** 특히 딥링크의 404 상태와 빈 링크 프리뷰.
- **`allPaths()`가 사라졌다.** 프리렌더 목록의 유일한 정의였고 이제 부르는 곳이 없다.
  프리렌더를 다시 켠다면 그 함수부터 되살려야 한다 — 커밋 719e316에 있다.
- **CI가 세던 것이 바뀌었다.** "엔트리 개수만큼 문서가 있는가"는 이제 물을 수 없는 질문이다.
  대신 셸이 **라우트 내용을 담지 않았는지**를 본다. 그것이 깨지면 모든 딥링크에서 하이드레이션이
  깨지므로, 이 사이트에서 가장 값비싼 단일 회귀다.
- **`app/routes/404.tsx`는 여전히 프리렌더러를 위해서만 존재한다.** 셸을 렌더할 200 응답이
  필요하고, 내비게이션 탭이 하나도 활성이 아닌 유일한 주소이기 때문이다(ADR 0010).

## 다시 열 조건

- **크롤러나 링크 프리뷰가 실제로 문제가 되면.** 이 저장소가 공개 카탈로그인 한 언젠가는
  그럴 것이고, 그때 되돌리는 것은 `vite.config.ts`의 `prerender` 블록과 `allPaths()`를
  되살리는 일이다. 커밋 719e316이 그 상태다.
- **딥링크의 404 상태가 무언가를 깨뜨리면.** 정적 호스트에서 이것을 피하는 다른 길은 해시
  라우팅(`/#/system/daniels`)뿐이고, ADR 0001이 처음에 버린 것이 바로 그것이다. 그 길로
  돌아가는 것은 프리렌더를 되살리는 것보다 나쁘다.
- **번들이 실제 독자에게 측정된 문제가 되면.** 지금은 149 kB gzip이고, 그중 절반이 코퍼스다.
